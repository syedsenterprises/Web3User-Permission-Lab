Enterprise Off-Chain Permission & Authorization Governance for Web3

Make transaction rules easier to inspect, test, and reason about.

Web3User Permission Lab is an off-chain transaction authorization and governance SDK for Node.js. Its architecture has advanced from the core ERC-20 policy evaluator into persistent authorization governance, cumulative budgets, monotonic witness infrastructure, hardware-backed Cloud KMS signing (AWS KMS & GCP Cloud KMS), and a verified pure state machine reducer for distributed consensus. The current public site remains an informational static preview: it is not a hosted authorization API, production wallet, transaction broadcaster, or production security service.

Implemented Security & Durability Foundation

Hardware-Backed Cloud KMS/HSM Signing

Production signer adapters for AWS KMS and GCP Cloud KMS with full DER-to-raw RFC 8410 64-byte Ed25519 signature normalization, algorithm contract enforcement, and factory resolution.

Deterministic Consensus State Reducer

Pure state machine reducer governing distributed consensus log events with 11 action types, single-slot idempotency, atomic epoch transitions, and strict monotonic index enforcement.

Multi-Process Race & Replay Prevention

Deterministic IPC rendezvous barriers release competing OS processes simultaneously to attempt consuming the same V3 authorization; tests strictly enforce exactly one ALLOW and three domain-level DENY outcomes with one persistent record.

Transaction Rollback & Contention Retries

Immediate SQLite write transactions (BEGIN IMMEDIATE;) roll back partial writes and intermediate clock updates on failure. Bounded retry loops with non-spinning sleep resolve transient contention or fail closed predictably.

Authorization & Signing-Key Boundaries

Rigorous boundary tests enforce strict rejection at the exact expiration second (nowSeconds >= expiresAtSeconds), clip expiry to authoritative policy/key caps, and enforce key validity windows and post-retirement forgery rejection.

Monotonic Clock & Replay Protection

ClockGuard monotonic time anchoring prevents time-travel attacks. Monotonic clock high-water marks, policy revisions, key governance states, and SQLite WAL schemas survive restarts without corruption.

      Architectural Boundary Notice

      What is running in your browser: The policy evaluation, cumulative window budget checks, ERC-20 transfer calldata decoding, parameter normalization, and rule checks shown above run 100% client-side in pure JavaScript. No data is transmitted to an external server.

      What requires Node.js runtime: Full cryptographic Ed25519 authorization signing, monotonic ClockGuard anchoring, persistent single-use replay protection, and multi-process atomic budget accumulators require the Node.js SDK (Web3UserEngine) with built-in SQLite WAL mode. To test multi-process replay attacks and persistent locking on your machine, run npm run demo:persistent-replay.

      Technical Snapshot

      Language: TypeScript · Tooling: Node.js (>=22.13.0), npm, Vitest · Storage: SQLite (built-in node:sqlite, WAL mode) · Signatures: Ed25519 (node:crypto) · Version Control: Git & GitHub.

      Current supported selector: 0xa9059cbb — ERC-20 transfer(address,uint256). The prototype enforces single-use persistent replay protection and atomic cumulative budgets over fixed UTC hourly and daily windows. Arbitrary smart contract parsing and universal wallet enforcement boundaries are not implemented.
