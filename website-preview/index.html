◈ Web3User Permission Lab
DEVELOPMENT PREVIEW · v0.2.0
Explicit permissions for Web3 actions

Make transaction rules easier to inspect, test, and reason about.

Web3User Permission Lab is an early-stage prototype exploring how proposed blockchain actions can be checked against clear rules before authorization. The current code supports a narrow ERC-20 transfer policy evaluator—not a wallet or transaction enforcement product.

Read the white paper (PDF) Open project mindmap
Development-stage notice: This project is experimental and has not been independently security-audited. It does not sign, submit, block, or enforce transactions. Do not use it to protect real funds or authorize production transactions.

What exists today

Policy evaluator

A TypeScript prototype checks one ERC-20 transfer call format and returns ALLOW, DENY, or UNKNOWN.

Input validation

It decodes the recipient and amount from calldata and checks policy rules, validity windows, and revocation.

Test baseline

The recorded development baseline has 34 passing tests and a successful TypeScript check.

Design principles

Fail closed

DENY and UNKNOWN must never be treated as approval by a future integration.

Least privilege

Permissions should be limited by target, recipient, amount, time, and scope.

Evidence over claims

Distinguish implemented features from planned work; tests are not a security audit.

Technical snapshot

Language: TypeScript · Runtime/tooling: Node.js and npm · Tests: Vitest · Type checking: TypeScript compiler · Version control: Git and GitHub.

Current supported selector: 0xa9059cbb — ERC-20 transfer(address,uint256). Cumulative budgets, replay protection, chain-aware transaction binding, and enforcement are not implemented.
